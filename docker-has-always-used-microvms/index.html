Docker has always used microVMs

Docker is all microVMs now? Always has been.

Back in 2015

When I joined Docker in 2015 the state of the art was "Docker Toolbox". It used VirtualBox, which is a fully featured VMM product. It had its own GUI and its own update process, and way more features than we needed (and lacked a few really useful ones).

A library VMM

We started building a thing we later thought of as a "library VMM": a VMM which could be embedded inside the application, and which would be single purpose, minimal, secure and fast. The first version was called hyperkit and the most recent one is "Docker VMM" .

The VM kernel and root filesystem were minimal too, based on the LinuxKit project. The current version is an even more slimmed down variant but conceptually the same .

What this gave us

For Docker Desktop this allowed:

  • Running rootless on all platforms. But not "rootless inside Linux": the whole Linux kernel is untrusted, so even a Linux CVE doesn't matter.
  • Minimal devices. We could carefully control the host / VM interface.
  • VPNs and network policy. It was easy to interoperate with VPNs, and to impose L7 networking policy in the form of RAM.

And now

The Docker microVM tech is the foundation of Docker Sandboxes today (why microVMs). It continues to get faster, lower overhead and more secure over time.
